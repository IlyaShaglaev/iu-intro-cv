## A. Панорама

Соберите собственный стичер: SIFT или ORB → дескрипторы → kNN + ratio test →
свой нормализованный DLT в своём RANSAC → общий холст → warp → feathering
или multi-band blending. `cv2.Stitcher` используйте только для сравнения в отчёте.

Обязательные функции (имена/сигнатуры сохраняйте):

| Функция | Что реализовать |
|---|---|
| `normalize_points` | Нормализация Хартли: центроид в нуле, среднее расстояние √2; вернуть точки и T |
| `dlt` | Система 2N×9, SVD, денормализация `inv(T_dst) @ H_norm @ T_src`, нормировка H[2,2]=1; отказ при вырождении |
| `ransac_homography` | Выбор четырёх пар, свой DLT, маска по расстоянию репроекции, лучшая модель и уточнение по инлаерам; воспроизводимое зерно |
| `match_points` | SIFT/L2 или ORB/Hamming; ratio test только для пар из двух соседей; честный отказ без признаков |
| `feather_blend` | Холст по преобразованным углам, общий сдвиг, маски покрытия, взвешенная сумма; чёрные пиксели не являются признаком отсутствия кадра |

Снимите свою серию **не менее четырёх кадров** с перекрытием, вращая камеру
примерно вокруг одного центра. Отдельно снимите серию с заметным параллаксом.
Приложите обе панорамы, исходники, параметры и разбор швов/двоения.
Цель — отсутствие видимых швов на основной серии; метрика ошибки гомографии
сама по себе этого не гарантирует. Выбор детектора и blending обоснуйте.

**Согласованный контроль DLT:** файл `correspondences.json` содержит точные
синтетические соответствия. Сравните со `cv2.findHomography(src,dst,method=0)`;
обе матрицы разделите на свой H[2,2]. Требование:
`np.linalg.norm(H_mine/H_mine[2,2] - H_cv/H_cv[2,2], ord='fro') < 1e-6`.
Это отдельный тест численной корректности, а не требование совпадения двух
алгоритмов на произвольных шумных матчах. Нормализация Хартли обязательна и в нём.
На шумных данных измеряйте среднюю ошибку репроекции инлаеров в пикселях и их долю.

## B. AR на плоскости

Опорное изображение — постер/обложка. Для каждого кадра видео найдите соответствия,
оцените H, наложите текстуру на плоскость. Реализуйте `smooth_homography`
(сглаживание проекций четырёх углов и восстановление H) и `overlay` (варп и маска).
Проанализируйте дрожание с `alpha=1` и сглаживанием, задержку и потерю цели.
При потере соответствий старую накладку не оставляйте висеть в воздухе.

```powershell
python panorama.py ar data/reference.png data/texture.png --source 0 --display -o out/camera.mp4
python panorama.py ar data/reference.png data/texture.png --source data/input.mp4 -o out/ar.mp4 --alpha 0.4
```

Окно и камера требуют локального запуска; Esc завершает просмотр. Входной видеофайл
позволяет проверить тот же цикл без камеры. Готовую обвязку CLI менять можно,
но сигнатуры проверяемых функций сохраняйте. 3D-куб — возможное расширение;
базовый вариант — плоская текстура, геометрически согласованная с опорой.

## Числа и отчёт

Заполните `REPORT.md`: команды, версии, seed, свои исходники и результаты,
контроль DLT, пары кадров/число матчей/доля инлаеров/ошибка репроекции,

с найденной целью, влияние сглаживания и причины отказа при параллаксе.
Для количественного сравнения сглаживания выберите неподвижную опору и
измерьте RMS перемещения проекций её углов; укажите длину фрагмента и alpha.
Не используйте абсолютный порог FPS как гарантию работы на чужом процессоре.

Ожидаемые результаты и допуски — в `sample_data/README.md` и `case*/expected.json`.
Зелёные тесты подтверждают базовую корректность; собственная съёмка, AR и анализ
отказов оцениваются по [рубрике](rubric.md), 100 баллов = 8 % курса.
30 баллов относятся к пяти закрытым примерам проверяющего; настройка одна,
из отчёта, без подстройки к каждому закрытому примеру.
