# Данные занятия 11 — калибровка камеры

Базовая часть работает офлайн: изображения генерирует готовая функция
`make_scene()` внутри `lab11.ipynb`. Скачиваний, камеры и внешних файлов нет.
Выберите окружение курса: `opencv-contrib-python==4.14.0.94`.

## Состав и геометрия

- 20 ракурсов ChArUco, 640×480, grayscale uint8; дополнительный пустой кадр
  проверяет корректный пропуск нераспознанного наблюдения.
- `cv2.aruco.CharucoBoard((7,5), 0.03, 0.021, DICT_4X4_50)`: 7×5 **клеток**,
  6×4 внутренних угла, размеры в метрах. Не путать с 7×5 внутренними углами
  обычной шахматки из примера HW4.
- Текстура `generateImage((1120,800), marginSize=0, borderBits=1)`;
  рендер через обратные лучи с дисторсией, пересечение с Z=0 доски и `remap`.
  Формулы поз даны в генераторе; K_GT = [[720,0,320],[0,700,240],[0,0,1]],
  dist_GT = [-0.16,0.04,0.001,-0.0008,0]. Это заданные параметры симулятора,
  а не результаты калибровки.
- После детекции в копию координат кадра 7 добавляется гауссов шум σ=4 px
  (`np.random.default_rng(11)`). Рендеры не меняются; исходные координаты сохранены.
  Это явная имитация ошибки локализации для эксперимента с отбраковкой.
- ⭐: `make_scene(pattern='chessboard')` рисует обычную шахматку в той же геометрии.

И K, и dist оцениваются из найденных на изображениях углов. Параметры GT
не передаются ни в `calibrateCameraExtended`, ни в `solvePnP`.
Объектные точки (N,1,3) — метры, изображения (N,1,2) — пиксели;
порядок соответствий определяет ID угла. Разрешение в OpenCV — (W,H).

## Самопроверка

`python -m pytest labs/lab11-calibration/tests -q` из корня публичного репозитория.
Незаполненные TODO пропускают соответствующие численные тесты. После заполнения
все тесты должны пройти. Ноутбук до заполнения останавливается на TODO 1.
Проверки на синтетике: 20 принятых поз, пустой кадр отклонён, по 24 угла;
после учебной отбраковки остаётся 19 поз. Контрольные интервалы RMS:
до 0.8–1.4 px, после 0.15–0.5 px; PnP <0.6 px. Это интервалы данного
эксперимента, а не универсальные нормы для собственной камеры.

SHA-256 (измерены на указанной версии OpenCV, сырые uint8 bytes в порядке C;
без заголовков PNG/NPZ):

| Поток байтов | SHA-256 |
|---|---|
| 21 кадр подряд: 20 поз + пустой | 1bed50e42f8f9c4ad54640e425ccc5cb6176eaff3276ddc623a9d2d8bc639571 |
| Текстура ChArUco 1120×800 | 40eb6cf39ea0e32e41b2195918d6173798dda2b32f45707cb12385bcfbd8ff56 |

Первую сумму печатает ячейка данных; вторую можно вычислить как
`hashlib.sha256(board.generateImage((1120,800), marginSize=0, borderBits=1).tobytes()).hexdigest()`.
При сравнении не добавляйте шум координат к байтам изображений.

## Уже имеющиеся свои фото

Укажите `OWN_DIR` в слоте ноутбука. Поддерживаются PNG/JPG/JPEG,
единое разрешение и та же конфигурация доски. Пустая папка, нечитаемый
файл и разные размеры дают понятную ошибку; синтетические GT-ассерты
и искусственный выброс отключаются. Не кладите личные фото в репозиторий.
Автофокус/цифровой зум должны быть фиксированы на всей серии. Для другой доски
измените её размеры и словарь; коэффициенты K не переносятся между разрешениями
без соответствующего преобразования пиксельных координат.

Малый RMS не доказывает точности на новых позах. Набор проверяет алгоритм,
но не заменяет реальную съёмку и метрологию, предусмотренные ТЗ HW4.
